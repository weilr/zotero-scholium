## Overview

zotero-scholium takes the output of reading a paper, whether written by a researcher or generated by a
language model, and stores it in Zotero as first-class objects: highlight and underline annotations with
comments, text annotations placed in the page margins, and child notes. The results appear in the Zotero
reader like annotations made by hand, can be edited there, and synchronise as ordinary library data.

The PDF file is never modified. On Zotero 10 and later the tool communicates with Zotero through the
official local API, which gained write support in Zotero 10.0; no plugin is required. Zotero 7 to 9 are
supported through a small bundled plugin.

The project is in an alpha state. The official-API path has been tested on Zotero 10.0.1 on Windows; the
plugin path for Zotero 7–9 is implemented but has received less testing.

## Features

- **Native annotations.** Highlights, underlines, and margin text are created as Zotero annotation items,
  not as marks inside the PDF. They are editable, searchable, and synchronised.
- **Margin notes with automatic layout.** Short summaries are rendered as text annotations beside the
  paragraph they refer to. Column geometry is measured from the page, boxes are placed on the
  paragraph's own side in two-column layouts, and overlaps with neighbouring boxes and the footer are
  resolved automatically. Annotations already present on the page, including the user's own margin
  notes, are read from Zotero beforehand and treated as occupied space.
- **Robust text matching.** Phrases are matched at word level, ignoring whitespace, hyphenation, and
  typographic ligatures, so text copied from a PDF extraction can be used verbatim.
- **Translation fidelity check.** Comments that mention terms or numbers absent from the highlighted
  text, or that are disproportionately long or short for the span, are reported as warnings before
  anything is written.
- **Profile learning.** `scholium profile --from-library` analyses the annotations already present in
  the library (colours, annotation types, comment length and style, density) and produces a profile
  that agents follow instead of a built-in style. Explicit user rules always take precedence.
- **Safe repeated runs.** Every object created by the tool carries an ownership tag. A re-run replaces
  only the tool's own annotations; the user's annotations are untouched, and existing notes are never
  deleted.
- **Three write channels.** The official local API (Zotero 10+), a bundled plugin (Zotero 7–9), and a
  generated script for manual execution, selected automatically.
- **Agent integration.** A ready-made Claude Code skill drives the whole workflow from a single request;
  any other agent framework can use the command-line interface in the same way.

## Requirements

- Python 3.9 or later
- [PyMuPDF](https://pymupdf.readthedocs.io/) (`pip install pymupdf`)
- Zotero 7 or later, running with its local server enabled (the default)
- For Zotero 7–9 only: the bundled `scholium-bridge` plugin

## Installation

```bash
pip install pymupdf
pip install .
```

This installs the `scholium` command. The single-file module `src/zotero_scholium/cli.py` can also be
executed directly without installation.

## Quick start

1. **Locate the item and its PDF attachment** through the local API (Zotero must be running):

   ```
   http://localhost:23119/api/users/0/items?q=<title words>
   http://localhost:23119/api/users/0/items/<ITEM_KEY>/children
   ```

2. **Write a configuration file.** A complete template is provided in
   [`skill/zotero-scholium/examples/config.template.json`](skill/zotero-scholium/examples/config.template.json).

   ```json
   {
     "pdf": "/path/to/Zotero/storage/<ATTACHMENT_KEY>/paper.pdf",
     "item_key": "<ITEM_KEY>",
     "attachment_key": "<ATTACHMENT_KEY>",
     "out_dir": "out",
     "note_html": "reading_note.html",
     "note_title_prefix": "Paper title",
     "highlights": [
       {"page": 1, "core": true, "text": "exact sentence from the PDF", "comment": "comment or translation"}
     ],
     "summaries": [
       {"page": 1, "anchor": "a unique phrase in the paragraph", "text": "a one-sentence margin note"}
     ]
   }
   ```

3. **Generate, review, and apply.**

   ```bash
   scholium --config config.json            # match text, render previews, report unmatched phrases
   scholium --config config.json --apply    # write into Zotero (Zotero 10: confirm the dialog once)
   scholium --config config.json --list     # read back what is currently stored in Zotero
   ```

   The first command writes `annotations.json`, a fallback `create_annotations.js`, and
   `preview_p<N>.png` for the configured pages, and lists any phrases that could not be located. Close
   and reopen the PDF in the Zotero reader after applying to display the new annotations.

## Learning the user's annotation profile

Annotation conventions differ between users: colours carry different meanings, some users underline,
some write in the margins, and some never add comments. Rather than imposing a style, the tool can
analyse the annotations already in the library and describe them.

```bash
scholium profile --from-library      # read-only; writes profile.json and profile.md
```

`profile.md` is written to `%APPDATA%/zotero-scholium/` on Windows and `~/.config/zotero-scholium/`
elsewhere. It contains three sections with increasing precedence:

| Section | Content | On re-run |
|---|---|---|
| Statistics | colours and their frequency, annotation types, comment length and style, density, notes | regenerated |
| `## Interpretation` | the meaning of each colour and the conventions new annotations should follow, completed by the agent and corrected by the user | preserved |
| `## User's rules (always win)` | explicit instructions from the user, in their own words | preserved |

Annotations created by the tool are excluded from the statistics, so the profile continues to describe
the user's own practice.

## Backends

| `--backend` | Zotero | Mechanism |
|---|---|---|
| `api` (default on 10+) | 10.0 and later | Official local API with write support. `POST /api/local/authorize` shows a confirmation dialog once; the key is stored per Zotero instance in the user configuration directory. |
| `bridge` | 7–9 | The bundled plugin [`plugin/scholium-bridge`](plugin/README.md) exposes data-only endpoints on localhost, protected by a token file in the Zotero data directory. Install it through Tools → Plugins → Install Plugin From File. |
| `js` | any | Writes `create_annotations.js` for manual execution in Tools → Developer → Run JavaScript. |

`--backend auto` selects the first available channel in the order listed.

## Configuration

| Key | Required | Description |
|---|---|---|
| `pdf` | yes | path of the PDF attachment |
| `item_key`, `attachment_key` | yes | Zotero keys of the parent item and the attachment |
| `out_dir` | yes | directory for generated files |
| `highlights[]` | | `page` (1-based), `text` (verbatim), `comment`, and one of `level`, `color`, or the legacy boolean `core`; optional `type: "underline"` |
| `summaries[]` | | `page`, `anchor` (a unique phrase locating the paragraph), `text` (without hard line breaks) |
| `levels` | | named colours, e.g. `{"claim": "#ff6666", "term": "#ffd400"}` |
| `note_html`, `note_title_prefix` | | HTML file of the child note; the prefix identifies an existing note with the same title |
| `author` | | `annotationAuthorName` shown in the reader (default: empty) |
| `core_color`, `other_color`, `text_color` | | defaults `#ff6666`, `#ffd400`, `#1a73e8` |
| `font_size` | | font size of margin text in points (default 8) |
| `preview_pages` | | pages rendered as PNG previews (default `[1]`) |
| `data_dir` | | Zotero data directory (bridge backend; inferred from the PDF path by default) |
| `cleanup_external` | | bridge backend only: also remove annotations imported from the PDF file (default `false`) |
| `note_replace` | | delete existing child notes with the same title prefix before creating the new one (default `false`; destructive) |

## Safety model

- The PDF is opened read-only and is never written to.
- Every annotation and note created by the tool carries the tag `zotero-scholium`. A re-run deletes
  only annotations that carry this tag, that have the configured author name, or whose content is
  identical to what is about to be created.
- Existing child notes are never deleted. If a note with the same title exists, the new note receives a
  versioned title of the form `Title (v2, YYYY-MM-DD)`.
- Annotations imported from the PDF file (shown as locked, "external" annotations) are left in place
  unless `cleanup_external` is enabled.
- Local API keys and plugin tokens are stored locally and are excluded from version control.

## Use with agents

[`skill/zotero-scholium/`](skill/zotero-scholium/) is a [Claude Code](https://claude.com/claude-code)
skill. After copying the directory into `~/.claude/skills/`, a request such as "annotate this paper in
Zotero" is carried out end to end: the skill instructs the model how to locate the item, which sentences
to highlight, how to write comments and margin notes in the register of a researcher's own notes, and
how to invoke this tool. A detailed style guide for Chinese output is included in
`references/style-zh.md`.

[`examples/direct_api_example.py`](examples/direct_api_example.py) demonstrates the underlying Zotero 10
local API calls in approximately thirty lines for use in other applications.

## How it works

1. The PDF is opened read-only with PyMuPDF and every page is indexed at word level.
2. Each highlight phrase is matched against the normalised word sequence; one rectangle per text line is
   produced in PDF user space, together with Zotero's sort index.
3. The body columns are estimated from the distribution of word coordinates. Each summary is anchored to
   the first line of its paragraph and laid out in the adjacent margin, with overlaps resolved.
4. The annotation objects are written through the selected backend, after removing the tool's own
   annotations from a previous run.

The verified JSON structure of annotation items, the authorisation flow of the local API, and the
reasoning behind the backend order are documented in [docs/design.md](docs/design.md).

## FAQ

**The annotations do not appear after applying.**
Close and reopen the PDF in the Zotero reader; open reader tabs do not reload annotations created
externally.

**Some phrases are reported as `missed`.**
The phrase spans a page break, contains a symbol that the extraction renders differently, or a small-caps
word is joined to its neighbour in the extraction. Choose a shorter substring within one page.

**Zotero shows the authorisation dialog again.**
Local API keys are bound to the `Zotero-Server-ID` of the instance. Reinstalling Zotero or moving the data
directory changes the ID, and a new key is requested.

**Some annotations are shown as locked.**
These were imported by Zotero from annotations embedded in the PDF file. The tool does not create such
annotations and, by default, does not remove them.

## Development

```bash
pip install -e ".[dev]"
pytest                                      # tests use a synthetic PDF; no third-party content
python scripts/check_skill_script_sync.py   # the skill bundles a copy of cli.py that must stay identical
```

The plugin is packaged by the release workflow; to build it locally, archive `manifest.json` and
`bootstrap.js` from `plugin/scholium-bridge/` at the root of a zip file named `scholium-bridge.xpi`.

## Contributing

Bug reports and pull requests are welcome. Please open an issue describing the Zotero version, the
operating system, and the backend in use, and include the output of the failing command with
`--list` where applicable. Changes to `src/zotero_scholium/cli.py` must be mirrored into the skill with
`python scripts/sync_skill_script.py`; the CI workflow enforces this.
