# Write channels and pitfalls

`scholium.py --apply` selects a backend automatically (`--backend` forces one):

| Backend | Zotero | Notes |
|---|---|---|
| `api`: official local API | 10 and later (preferred) | The first run opens an "Allow / Always Allow" dialog in Zotero; tell the user in advance to choose "Always Allow". The key is stored under `%APPDATA%/zotero-scholium/` (or `~/.config/zotero-scholium/`). No plugin is required. |
| `bridge`: plugin | 7 to 9 | The local API is read-only before Zotero 10. Ask the user once to download `scholium-bridge.xpi` from https://github.com/weilr/zotero-scholium/releases and install it (Tools → Plugins → gear icon → Install Plugin From File). |
| `js`: script file | fallback | `create_annotations.js`, to be executed in Tools → Developer → Run JavaScript with "Run as async function" enabled. |

Do not write to `zotero.sqlite` directly (the database is locked while Zotero is running), and do not attempt to obtain tokens from other plugins' endpoints.

## When `applied` is `false`

`apply_error` names the cause:

- `missed` or `style_warnings` non-empty: correct the configuration and run again.
- Zotero 7–9 without the plugin: guide the installation, then run again.
- No write channel: let the user run `create_annotations.js` (path in `fallback`).
- An HTTP error from the local API: report it verbatim; a renewed authorisation dialog after reinstalling Zotero or moving the data directory is expected, since keys are bound to the instance's `Zotero-Server-ID`.
- Partial writes or failed read-back: inspect any available `result` and run `--list` to reconcile actual stored annotations and notes before retrying. HTTP exceptions may leave no result; `applied: false` does not mean nothing was written.

## Pitfalls

- Locked or duplicated annotations originate from a PDF that once contained annotations; Zotero imports them as external. Never write into the PDF, and leave external annotations untouched unless the user asks otherwise (`cleanup_external`, bridge backend only).
- Hard line breaks in text annotations make them impractical to edit.
- Follow the user's colour rules; otherwise use the profile or default core/other levels.
- Never delete a user's notes, including earlier versions generated by the tool (`note_replace` stays `false`).
- The tool does not write `annotationAuthorName`. API, bridge and generated JavaScript recognise ownership only by `zotero-scholium` or the legacy tags `zotero-marginalia`, `zotero-paper-annotate`; identical content alone never establishes ownership. The bridge's explicit `cleanup_external` option is separate.
- Open reader tabs do not reload annotations created externally: close and reopen the PDF.
