# 中文写作规范：研究者自用笔记的语体

本规范规定译文、页边批注和阅读笔记三类文字的写法。目标是使生成的内容读起来像研究者本人在阅读过程中留下的记录，而不是面向他人的摘要或新闻稿式的概述。问题的关键不在术语，而在语体。

## 译文（高亮评论）

译文只对应高亮范围内的文字，不增不减。不补充高亮之外的上下文（同一句的其余部分、相邻句子、公式编号、模型名称），不加入读者的解释或评价，也不省略高亮中的任何成分。若高亮片段过短、单独翻译不成句，应当扩大高亮至整句，而不是在译文中补足。在此前提下，译文须准确，但准确不等于逐词对译：先理解原句的含义，再用中文完整表达。

每条译文按下面的指令生成，`${sourceText}` 为高亮范围内的原文；评论中只放译文本身，不附原文、备注或备选译法：

```
As an AI academic expert, translate the following English text to Chinese with native fluency and technical precision. Keep core ML terms (attention, transformer, loss, etc.) and model/dataset names in English. Use standard Chinese translations for established concepts. Make it read naturally for Chinese researchers.
Text: ${sourceText}
Output only the translation.
```

- 按中文习惯断句。英文长句通常需拆为两句；被动句多数改为主动句或无主句。
- 术语保留原词或加括注：`patch jittering`、`tokenization`、`FSDP` 等直接保留英文，或在首次出现时写作"补丁抖动（patch jittering）"。不生造"令牌化""分片化"之类的硬译。
- 论文中的 "we" 译为"我们"或"作者"均可，全篇保持一致。
- 去除翻译腔："进行 X"通常可直接使用动词；"……的这一事实""通过……的方式""对于……而言"多为英文结构的残留，应予改写。
- 数字、百分比、模型名称原样保留。

对照：
> 不宜：我们引入了新的方法来缓解这些障碍，包括基于调和分析的稳定化方法、负载均衡的 2D-3D 分布式训练策略，以及计算自适应的 tokenization。
> 宜：为了缓解这些障碍，我们引入了几项新方法：一种基于调和分析的稳定化方法、负载均衡的 2D-3D 分布式训练策略，以及按算力自适应的 tokenization。

高亮片段与译文范围不一致的例子：
> 高亮：employs a space-time factorized transformer architecture
> 不宜：用的是时空分解的 Transformer：每个块里交替沿空间轴和时间轴做注意力。（后半句来自高亮之外）
> 宜：采用时空分解的 Transformer 架构。

## 页边批注（text 注释）

页边批注相当于研究者在纸质论文页边写下的话，用途是提示日后重读时的自己，而非为他人撰写摘要。

- 一至两句完整的话。不使用"标签：内容"格式，不使用 →、↓、①②③ 等符号，不堆砌括号缩写。
- 可以记录反应与判断："这个数字比预想的大得多""这里的对比并不公平，基线只微调了一次"。
- 可以提出问题："为什么只用轴对齐的旋转？任意角度会破坏边界吗？"
- 可以建立联系："与 VICON 的做法相同""这与第 8 页的消融结果是否矛盾？"
- 不必每段都写。没有实质内容时留空。
- 长度视内容而定，多数在 15–40 字；偶尔一句简短的"关键一步"亦可。

对照：
> 不宜：分布式：token对齐、差异化批大小、拓扑感知采样→吞吐+262%
> 宜：三项措施合计带来 262% 的吞吐提升，其中拓扑感知采样贡献最大，本质是避免同一 FSDP 组内的设备相互等待。

> 不宜：关键洞见：预训练指标更差，下游却更好；3D数据必须进入预训练
> 宜：全文最值得注意的一处：增强越强，预训练损失越差，下游反而越好。按预训练 loss 选方案会选错。

## 阅读笔记（子笔记）

阅读笔记是读完全文后撰写的内容，篇幅数百字至一千字，面向数月后重读的自己。

结构可以松散，可用中文小标题，也可不用；以下内容通常应当包含，顺序与篇幅视论文而定：

- 开头两三句说明这篇论文做了什么、为何阅读它。
- 方法和结果中真正重要的几点，附具体数字。写"在 19 个数据集上单步误差平均下降约六成"，而不是"取得了显著提升"。
- 读者的判断：哪些结论可信、哪些存疑、与自身工作的关系、哪些想法可以借用。允许写"尚未想清楚"。
- 局限性引用作者本人的表述，并补充读者的观察；不写成"挑战与展望"式的固定段落。
- 结尾给出完整引用和代码链接即可，不写"Written by …"之类的落款。

写法：

- 以段落为主；列表仅用于真正并列的清单，列表项不以粗体标签开头。
- 不使用"值得注意的是""不仅……而且……""从……到……""标志着""彰显""赋能"等套语；不用破折号制造停顿；不用表情符号；不为每段配一句格言式的收尾。
- 句子长短交错。连续三句长度相同时改写其中一句。
- 可以使用第一人称。"我怀疑……""我更关心……"比"研究者可能会关注……"更诚实。
- 明确表达不确定："附录中的线性平流实验过于简单，结论能否推广到真实系统尚不清楚。"

对照（同一段内容）：
> 不宜：**预训练策略消融（最重要的洞见）**：全增强的模型预训练指标反而更差，但下游迁移显著更好 → 受限数据集上漂亮的预训练指标可能误导；仅 2D 预训练在 3D 任务上小数据时略有帮助、数据增多后反成拖累；含 3D 预训练的完整模型优势压倒性 → 必须把 3D 数据纳入预训练。
> 宜：消融实验是我认为最有价值的部分。作者用半尺寸模型比较了三种预训练方案：完整增强、仅 2D 且不做增强、从头训练。仅看预训练 loss，完整增强一组最差；换到下游任务，它又是最好的，无论分布内还是全新任务。这说明依据预训练指标选择方案会出错，而且我推测不少论文中"更好的预训练结果"正是这样得来的。另一个细节：仅用 2D 预训练的模型在 3D 任务上，数据少时略有帮助，数据一多反而拖累。因此 3D 数据必须进入预训练。

## 页首总结（首页顶部的 text 注释）

仅在画像或用户要求时写。三四句话，放在首页标题上方，是日后打开这篇 PDF 第一眼看到的内容。

- 第一句用自己的话说这篇论文做了什么，不以"本文提出"开头。
- 第二句给最关键的一个数字或结果。
- 之后一两句是读者的判断：最值得记住的是什么，哪里存疑。
- 不复述摘要，不罗列贡献，不写"具有重要意义"。

对照：
> 不宜：本文提出了 Transformer，一种完全基于注意力机制的新型网络架构，在机器翻译任务上取得了显著提升，具有重要的研究意义。
> 宜：这篇论文把序列模型里的循环和卷积全部去掉，只用注意力。WMT14 英德翻译 BLEU 28.4，8 块 P100 训练 3.5 天。我认为最值得记住的不是分数，而是可并行带来的训练成本下降；正弦位置编码与学习式编码的对比并不充分。

## 交付前检查

通读所有评论和笔记，逐条核对：

1. 是否有"标签：内容"式的批注？改为句子。
2. 是否有 →、↓、①②③、【】或粗体标签？删除或改写。
3. 是否有"值得注意""不仅……而且""标志着""关键洞见""核心贡献"等套语？换成具体表述。
4. 译文是否只对应高亮范围内的文字？译文中出现而高亮中没有的数字、公式编号、模型名或补充说明一律删去，或扩大高亮。
5. 译文是否符合中文表达习惯？拆分长句，去除"进行""对于……而言"。
6. 笔记中是否包含读者自己的判断和疑问？没有则尚未完成。
7. 是否连续三句长度相同？改写其中一句。
8. 结尾是否有落款或"未来展望"式的空话？删除。
